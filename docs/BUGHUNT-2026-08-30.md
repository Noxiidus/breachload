# Bug hunt — 2026-08-30 (v0.17.0 feature round)

Review pass over the v0.17.0 additions (fingerprint→CVE depth, network robustness,
AD kill-chain composer, HTML report). Two real bugs found and fixed; the rest of the
new code held up.

## Bugs found & fixed

### 1. nuclei CVE-id passthrough never fired in the real pipeline
**Where:** `core/llm.py` (`_nuclei_cve_ids` / the VULN nuclei branch).
**Symptom:** the new "confirm the exact CVE with `nuclei -id`" path keyed off the
service *notes*, but the web-CVE matcher (`analysis/webcve.py`) records its lead as a
**Finding** (`cve=[...]`), not as a `svc.notes` entry. So in a normal run the notes
never contained a `CVE-…` token and the passthrough silently degraded to the tag path.
**Fix:** added `_service_cve_ids(state, host, svc)` which unions the note-derived ids
with the CVEs of any Finding attached to that host/service, and pointed the planner at
it. The passthrough now fires whenever a KB lead exists. Regression:
`test_planner_uses_cve_from_finding`.

### 2. adchain misclassified UPN users as computers (bad RBCD step)
**Where:** `analysis/adchain.py` (`_looks_like_computer`).
**Symptom:** the check treated any name containing a `.` as a computer, so a
`GenericWrite`/`GenericAll` edge over a UPN user (`jdoe@corp.local`) or a bare domain
(`corp.local`) was emitted as an **RBCD** step instead of ACL-abuse — a wrong, dead-end
recommendation.
**Fix:** a computer is now a `$`-suffixed SAM name or a 2+-dot FQDN host; a UPN (`@`) or
a single-dot domain is excluded. Regression covered by the existing
`test_rbcd_for_computer_target` / `test_generic_write_over_user_is_acl_abuse`.

  contain no validator-blocked metacharacters.

# Bug hunt - 2026-08-30 (v0.20.0: proof/validation, MCP, browser)

Review pass over the v0.20.0 additions and the ASCII normalization. Four bugs
found and fixed; 684 tests green, ruff + mypy clean.

## Bugs found & fixed

### 1. MCP `parse_nmap_xml` was wired to the wrong field (dead tool)
**Where:** `mcp/server.py` `_tool_parse_nmap`.
**Symptom:** it passed the XML as `ToolResult(output_file=...)`, but `NmapAdapter.parse`
reads the XML from `stdout`. So the tool always saw empty stdout and returned "nmap
produced no XML" - the tool never worked. **Fix:** pass the XML as `stdout`.
Regression: `test_parse_nmap_xml_reads_real_xml`.

### 2. Reflected-XSS probe couldn't tell escaped from raw (over-reported HIGH)
**Where:** `analysis/browser.py` `probe_reflected_xss`.
**Symptom:** the canary was alphanumeric (`blxss7q3z`) with no angle brackets, so the
"unescaped" check (`&lt;canary` absent) was vacuously true whenever the canary
reflected - every reflection was flagged **HIGH**, even when the app correctly HTML-
encoded it. **Fix:** the canary now carries angle brackets (`<blxss7q3z>`); RAW
reflection = the brackets survive unencoded (real XSS candidate, HIGH), encoded-only =
LOW. Regressions updated in `test_browser.py`.

### 3. `_is_external(None)` could crash the browser analysis
**Where:** `analysis/browser.py` `_is_external`.
**Symptom:** a `None` script `src` (possible from a malformed DOM) would raise on
`.startswith`. **Fix:** guard `if not src: return False`.

### 4. MCP `fingerprint_to_cve` "no leads" branch was dead
**Where:** `mcp/server.py` `_tool_fingerprint_cve`.
**Symptom:** `json.dumps([]) or "no leads"` - an empty list serialises to `"[]"`, which
is truthy, so the friendly "no leads" message never showed. **Fix:** check the list
first. Regression: `test_fingerprint_no_lead_message`.
